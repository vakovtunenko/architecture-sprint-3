# Задание 1. Анализ и планирование

### 1. Описание функциональности монолитного приложения
**Управление отоплением:**
- Пользователи могут удалённо включать/выключать отопление в своих домах через веб-интерфейс.
- Пользователи могут устанавливать целевую температуру отопления через веб-интерфейс.
- Пользователи могут просматривать состояние обогревательной системы (включена/выключена, текущая/целевая температура) через веб-интерфейс.
- Система отправляет команды на включение/выключение/изменение целевой температуры обогревательной системе.
- Система получает данные о состоянии с обогревательной системы.

**Мониторинг температуры:**
- Пользователи могут просматривать текущую температуру в своих домах через веб-интерфейс.
- Система получает данные о температуре с датчиков, установленных в домах.

Далее включаем фантазию тк по требованиям и описанию из задания нет возможности увидеть полную картину происходящего.

**Регистрация устройств:**
- Специалисты по подключению могут регистрировать обогревательные системы, установленные в домах пользователей.
- Специалисты по подключению могут устанавливать датчики температуры в домах пользователей.
- Система получает данные о новом устройстве (обогревательная система/датчик температуры) в доме пользователя.

**Регистрация пользователей:**
- Специалисты по подключению создают учетную запись для пользователя при первом выезде к нему
- Система получает данные о новом пользователе

**Прием платежей:**
- Пользователи могут оплачивать различные услуги на сайте (вызов специалиста при не исправностях, установка дополнительных датчиков и тд)

### 2. Анализ архитектуры монолитного приложения
- **Язык программирования**: Java
- **База данных**: PostgreSQL
- **Архитектура**: Монолитная, все компоненты системы (обработка запросов, бизнес-логика, работа с данными) находятся в рамках одного приложения.
- **Взаимодействие**: Синхронное, запросы обрабатываются последовательно.
- **Масштабируемость**: Ограничена, так как монолит сложно масштабировать по частям.
- **Развёртывание**: Требует остановки всего приложения.

  - **Контекст: Управление освещением** - логика регистрации осветительных приборов, включение/выключение, настройка интенсивности освещения, просмотр состояния и тд

  - **Контекст: Управление воротами** - логика регистрации электронных замков, отпирание/запирание, просмотр состояния и тд 
- **Поддомен: Наблюдение за домом**
  - **Контекст: Наблюдение за домом** - логика регистрации наблюдательных приборов, просмотр получаемой информации и тд 

**Домен: Мониторинг и телеметрия**

- **Поддомен: Мониторинг**
  - **Контекст: Алертинг и реагирование** - реагирование на определенные показатели, алертинг пользователей

  - **Контекст: Аутентификационные данные пользователя** - хранение обычного логина/пароля, интеграция с различными провайдерами oAuth (яндекс, вк и тд)

**Домен: Оплата услуг**

  - **Контекст: Каталог услуг** - отвечает за управлением каталогом доступных услуг - выезд специалиста, продвинутые сценарии автоматизации, подписки и тд
